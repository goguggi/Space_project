# 08. 로켓 설계 프로그램 인수 문서 (설계 담당자용)

작성일: 2026-09-05
대상: 로켓 설계 프로그램을 만드는 팀원
목적: 설계 프로그램이 이 프로젝트(우주여행 시간 지연 계산기 + 3D 발사 시뮬레이션)와 어떻게 이어지는지,
무엇을 만들어야 하고 무엇을 지켜야 하는지를 한 문서로 전달한다.

이 문서만 읽어도 시작할 수 있도록 썼다. 더 깊은 배경은 각 절의 링크를 따라간다.

---

## 1. 전체 그림

```
[로켓 설계 프로그램]  --(로켓 제원 JSON 파일)-->  [우주여행 시간 지연 계산기 / 3D 발사 시뮬레이션]
   별도 저장소                                        저장소: goguggi/Space_project
   KSP처럼 3D 부품을 드래그로 조립                     설계된 로켓으로 발사 장면을 재생하고
   조립 결과를 JSON으로 내보냄                          단 분리, 재착륙, 시간 지연을 계산
```

- 두 프로그램은 **별도 저장소**에서 개발한다. (D-49)
- 연결 고리는 **로켓 제원 JSON 파일** 하나다. 설계 프로그램이 내보내고, 이 프로젝트가 불러온다. (D-48)
- 설계 프로그램은 **3D 부품 조립** 방식이다. 부품을 장면에 끌어다 붙여 로켓을 만든다. (D-50)
- 기술은 이 프로젝트와 동일하다: HTML / CSS / JavaScript(ES 모듈), Three.js, 화면·주석·문서 모두 한국어. (D-51)

## 2. 이 프로젝트가 하는 일 (설계 담당자가 알아야 할 만큼만)

1. 사용자가 발사장(5곳), 목적지(천체 12개), 속도(11.2 km/s ~ 0.99c), 편도/왕복을 고른다.
2. "발사" 버튼을 누르면 **3D 발사 장면**이 나온다. 로켓이 물리 계산(추력, 중력, 질량 변화)에 따라 상승하고, 단이 분리되고, 회수 가능한 단은 스페이스X처럼 재착륙한다.
3. 발사 장면이 끝나면 우주선이 지정 속도로 항해를 시작하고, 상대론적 시간 지연을 계산해 생물 5종의 수명과 비교해 보여준다.

설계 프로그램이 관여하는 부분은 **2번의 로켓**이다. 현재는 팔콘 헤비 제원이 코드에 고정되어 있는데,
설계 프로그램이 완성되면 사용자가 직접 설계한 로켓으로 발사 장면이 재생된다.

발사 물리의 자세한 내용은 [03_physics.md](03_physics.md) 6절에 있다. 요지는 다음과 같다.

- 운동 방정식: dv/dt = (T/m)·u − (GM/r²)·r̂, dm/dt = −T/(Isp·g₀). 공기 저항은 계산하지 않는다.
- 각 단은 추진제를 다 쓰면 분리된다. 분리 순서는 병렬 부스터 → 직렬 하위 단 → 상위 단.
- 회수 표시가 된 단은 부스트백 → 낙하 → 착륙 연소로 착륙한다. 착륙은 항상 성공하도록 계산한다.

## 3. 설계 프로그램이 만들어야 하는 것

### 3.1 기능 요구사항

| 번호 | 기능 | 설명 |
|---|---|---|
| R-01 | 부품 목록 | 화면 한쪽에 부품 목록(팔레트)을 두고, 종류별로 묶어 보여준다 |
| R-02 | 3D 조립 | 부품을 장면으로 끌어다 놓으면 다른 부품의 연결점에 붙는다. 세로로 쌓기(직렬)와 옆에 붙이기(병렬 부스터)를 모두 지원한다 |
| R-03 | 단 편성 | 붙인 부품들을 "단"으로 묶고 분리 순서를 정한다. 병렬 부스터는 별도 단으로 표시된다 |
| R-04 | 회수 설정 | 단마다 "회수(재착륙)" 여부를 켜고 끈다. 착륙 다리 부품이 있는 단만 회수를 켤 수 있다 |
| R-05 | 실시간 계산 | 조립할 때마다 총질량, 발사 시 추력대중량비(TWR), 단별 Δv, 총 Δv를 계산해 표시한다 (4절) |
| R-06 | 검증 | 발사 가능 조건(5절)을 확인하고, 문제가 있으면 한국어로 이유를 보여준다 |
| R-07 | JSON 내보내기 | 조립 결과를 6절의 형식으로 저장한다 (다운로드) |
| R-08 | JSON 불러오기 | 저장한 파일을 다시 열어 조립 상태를 복원한다 |
| R-09 | 기준 로켓 | 팔콘 헤비와 같은 구성을 미리 만들어 둔 예제로 제공한다 ([examples/falcon_heavy.rocket.json](examples/falcon_heavy.rocket.json)) |

### 3.2 부품 종류 (최소 집합)

부품 하나는 아래 속성을 가진다. 부품 목록의 실제 값은 설계 담당자가 정하되, 단위와 속성 이름은 6절의 형식을 따른다.

| 종류 (`type`) | 필수 속성 | 비고 |
|---|---|---|
| `engine` | 건조 질량, 해수면 추력, 진공 추력, 해수면 Isp, 진공 Isp | 팔콘 헤비의 멀린 1D: 해수면 845 kN, 진공 914 kN, Isp 282/311 s, 약 470 kg |
| `tank` | 건조 질량, 추진제 질량 | 추진제 질량은 사용자가 채우는 양(0~최대)으로 조절 가능해야 한다 |
| `payload` | 질량 | 우주선(탑재체). 기본값 10 t (D-43) |
| `fairing` | 질량 | 탑재체 덮개. 2단 점화 후 분리 |
| `decoupler` | 질량 | 단 경계. 이 부품 위아래가 다른 단이 된다 |
| `landing_legs` | 질량 | 붙어 있는 단만 회수 가능 |
| `booster_attach` | 질량 | 병렬 부스터를 옆에 붙이는 연결 부품 |

## 4. 설계 프로그램이 계산해야 하는 값 (물리 근거)

아래는 학술적으로 정해진 공식이므로 그대로 쓴다. 이 프로젝트의 검증 페이지와 같은 값이 나와야 한다.

| 값 | 공식 | 설명 |
|---|---|---|
| 총질량 m₀ | 모든 부품 건조 질량 + 추진제 질량의 합 | kg |
| 발사 시 추력대중량비 TWR | (첫 단에서 점화되는 엔진의 해수면 추력 합) / (m₀ · g₀) | 1보다 커야 이륙 |
| 단별 Δv | Isp_진공 · g₀ · ln(m_점화 시 / m_연소 종료 시) | 치올콥스키 로켓 방정식. m은 그 단 점화 시점에 로켓에 남아 있는 전체 질량 |
| 총 Δv | 단별 Δv의 합 | 병렬 부스터가 붙은 첫 단은 부스터 연소 구간과 코어 단독 구간을 나누어 계산 |
| 연소 시간 | 추진제 질량 / (추력 / (Isp · g₀)) | 초 |

상수: g₀ = 9.80665 m/s². 병렬 부스터가 있을 때의 Δv 계산 순서는 [03_physics.md](03_physics.md) 6.3절의 질량 표를 따른다.

## 5. 발사 가능 조건 (검증 규칙)

설계 프로그램은 내보내기 전에 아래를 확인한다. 이 프로젝트도 불러올 때 같은 검사를 하며, 실패하면 발사 버튼이 비활성화된다.

| 번호 | 조건 | 실패 시 안내 문구 (예) |
|---|---|---|
| V-01 | 탑재체가 정확히 1개 | "탑재체(우주선)를 하나 붙여 주세요" |
| V-02 | 단이 1개 이상, 각 단에 엔진 1개 이상과 탱크 1개 이상 | "N단에 엔진이 없습니다" |
| V-03 | 발사 시 TWR > 1 | "추력이 부족해 이륙할 수 없습니다 (TWR 0.8)" |
| V-04 | 회수를 켠 단에 착륙 다리가 있음 | "회수하려면 착륙 다리를 붙여 주세요" |
| V-05 | 회수를 켠 단의 남는 추진제 비율 ≥ 설정값 | 착륙 연소용 연료. 기본 5% (Q-20에서 확정) |
| V-06 | 총 Δv ≥ 9,400 m/s | 지구 저궤도 도달에 필요한 대략값. 미달이면 경고만 하고 내보내기는 허용 |
| V-07 | 부스터 단은 반드시 병렬(옆에 붙음)이고, 직렬 단은 위아래로만 연결 | 구조 오류 |

## 6. 로켓 제원 JSON 형식 (두 프로그램의 계약)

파일 확장자는 `.rocket.json`, 인코딩은 UTF-8, 단위는 **모두 SI 기본 단위**(kg, N, s, m)다.
이 형식을 바꿔야 하면 반드시 양쪽이 합의하고 `formatVersion`을 올린다.
완전한 예시는 [examples/falcon_heavy.rocket.json](examples/falcon_heavy.rocket.json)에 있다.

```json
{
  "formatVersion": 1,
  "name": "팔콘 헤비 (예제)",
  "createdAt": "2026-09-05T00:00:00Z",
  "designer": "이름",
  "payloadMassKg": 10000,
  "stages": [
    {
      "id": "core",
      "label": "중앙 코어",
      "role": "serial",
      "separationOrder": 2,
      "dryMassKg": 22200,
      "propellantMassKg": 411000,
      "engines": { "count": 9, "thrustSeaLevelN": 845000, "thrustVacuumN": 914000, "ispSeaLevelS": 282, "ispVacuumS": 311 },
      "throttleWhileBoosters": 0.6,
      "recovery": { "enabled": true, "target": "drone_ship", "reservePropellantFraction": 0.05 }
    }
  ],
  "geometry": {
    "parts": [
      { "partId": "core-body", "type": "tank", "stageId": "core", "position": [0, 21, 0], "rotation": [0, 0, 0], "size": [3.7, 42, 3.7] }
    ]
  },
  "summary": { "totalMassKg": 1425000, "liftoffTwr": 1.6, "totalDeltaVMps": 12000 }
}
```

### 6.1 필드 설명

| 필드 | 필수 | 설명 |
|---|---|---|
| `formatVersion` | 예 | 형식 버전. 현재 1 |
| `name`, `createdAt`, `designer` | 예 | 표시용 |
| `payloadMassKg` | 예 | 탑재체(우주선) 질량. 기본 10,000 |
| `stages[]` | 예 | 단 목록 |
| `stages[].role` | 예 | `parallel`(옆에 붙은 부스터) 또는 `serial`(세로로 쌓인 단) |
| `stages[].separationOrder` | 예 | 분리 순서. 1부터. 병렬 부스터 2기는 같은 번호를 가질 수 있음 |
| `stages[].engines` | 예 | 그 단의 엔진 묶음. `count`개가 같은 제원. 추력과 Isp는 엔진 1개 값 |
| `stages[].throttleWhileBoosters` | 아니오 | 병렬 부스터가 붙어 있는 동안 코어 엔진 추력 비율(0~1). 없으면 1 |
| `stages[].recovery` | 예 | `enabled`, `target`(`launch_site` / `drone_ship`), `reservePropellantFraction`(착륙용으로 남길 비율) |
| `geometry.parts[]` | 예 | 3D 표시용. 위치, 회전, 크기(m). 이 프로젝트는 이것으로 로켓 모양을 그린다. 물리에는 쓰지 않는다 |
| `summary` | 아니오 | 설계 프로그램이 계산한 값. 이 프로젝트는 참고만 하고 자체 계산으로 다시 검증한다 |

### 6.2 이 프로젝트가 JSON을 읽는 방식

- 사용자가 발사 화면의 "설계한 로켓 불러오기" 버튼으로 `.rocket.json` 파일을 고른다. (16단계, [04_roadmap.md](04_roadmap.md))
- 파일을 5절 규칙으로 검증하고, 통과하면 `stages`로 발사 물리를, `geometry.parts`로 3D 형상을 만든다.
- 두 사이트가 같은 GitHub 계정의 Pages(같은 출처)에 있으면 파일 없이 브라우저 저장소로 바로 넘기는 방법도 가능하다. 이 방식의 채택 여부는 Q-19.

## 7. 지켜야 할 규칙 (이 프로젝트와 동일)

| 항목 | 규칙 |
|---|---|
| 언어 | 화면 문자열, 주석, 문서는 한국어. 변수, 함수, 파일 이름은 영어 |
| 모듈 | ES 모듈(`import`/`export`). 파일 하나는 역할 하나 |
| 폴더 | `src/data/`(부품 목록 등 숫자), `src/physics/`(계산, DOM 없음), `src/ui/`, `src/scene/`(Three.js), `src/utils/`, `lib/three/`, `docs/`, `tests/` |
| 폴더 README | 폴더마다 README.md 하나. 파일이 바뀌면 함께 갱신 |
| 문서 목차 | `docs/INDEX.md`에 모든 md 파일 목록 |
| Three.js | `lib/three/`에 동봉, ES 모듈 빌드, `src/scene/`에서만 import. 버전은 이 프로젝트와 맞춘다 |
| 실행 | GitHub Pages(main 루트). 로컬 확인은 로컬 서버 |
| Git | 단계마다 커밋. 커밋 첫 줄은 `N단계: 요약` |
| 의사결정 | 물리, 학술 사실이 아닌 결정은 임의로 하지 말고 팀에 묻고 기록 |

자세한 원칙은 [02_architecture.md](02_architecture.md)를 그대로 따른다.

## 8. 권장 개발 단계 (설계 프로그램)

| 단계 | 이름 | 완료 조건 |
|---|---|---|
| A0 | 계획, 문서, 폴더 골격 | 이 문서 기준으로 저장소 README, docs/INDEX.md, 폴더 README 작성 |
| A1 | 부품 데이터와 계산 엔진 | `src/data/parts.js`, `src/physics/massBudget.js`(총질량, TWR), `src/physics/deltaV.js`. tests에서 팔콘 헤비 예제로 검증 |
| A2 | JSON 내보내기, 불러오기 | 화면 없이도 예제 JSON을 만들고 다시 읽을 수 있음. 5절 검증 포함 |
| A3 | 빈 3D 장면과 부품 팔레트 | Three.js 장면, 조명, 바닥. 팔레트 목록 표시 |
| A4 | 드래그 조립 (직렬) | 부품을 끌어다 위아래로 붙임. 연결점 표시 |
| A5 | 병렬 부스터 붙이기와 단 편성 | 옆에 붙이기, 단 자동 구분, 분리 순서 편집 |
| A6 | 회수 설정과 실시간 계산 표시 | 단별 회수 켜기, 총질량, TWR, Δv 패널 |
| A7 | 연동 시험 | 내보낸 JSON을 이 프로젝트 16단계에서 불러와 발사 장면이 재생됨 |

A1, A2를 먼저 끝내면 이 프로젝트 쪽 16단계 개발을 동시에 진행할 수 있다.
